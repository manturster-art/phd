# UI Design Skill

Designer 에이전트가 사용. 모바일 우선·한국어 우선·접근성 기본의 UI 설계를 산출한다.

## 워크플로우

### 1. IA (Information Architecture)
원우회 앱의 기본 IA는 보통 하단 탭 4~5개:
- **홈**: 공지 + 다가오는 일정 위젯
- **게시판**: 자유/질문/공지 카테고리 탭
- **일정**: 캘린더 + 리스트
- **회원**: 디렉토리 + 내 프로필
- (선택) **더보기**: 회비, 행사, 관리 메뉴

햄버거 메뉴는 가능한 피한다. 모바일에서 발견성이 낮다.

### 2. 화면별 와이어프레임
ASCII 또는 Mermaid로 모바일 360~390px 기준 레이아웃. 각 화면은:
- 화면 ID (`SCR-001` 등)
- 진입 경로
- 핵심 영역 (헤더/리스트/CTA/FAB 등)
- 빈/로딩/에러 상태

예시:
```
┌─────────────────────┐
│ ☰  원우회         🔔 │  ← AppBar
├─────────────────────┤
│ 📌 [공지] 학기말 모임  │  ← Pinned Notice
├─────────────────────┤
│ ▣ 다가오는 일정 (3)  │  ← Section
│  └ 5/22 종강 파티   │
├─────────────────────┤
│ 📝 최근 게시글       │
│  └ ...              │
└─────────────────────┘
[홈][게시판][일정][회원]
```

### 3. 사용자 흐름
P0 스토리별로 Mermaid sequence/flowchart. 최소 다음 5개:
- 신규 가입 (이메일 인증 → 학번 입력 → 임원 승인 대기 → 활성화)
- 공지 작성 (임원, 첨부 포함)
- 게시글 + 댓글
- 일정 등록 + RSVP
- 회비 납부 확인

### 4. 컴포넌트 카탈로그
재사용 컴포넌트를 props/state와 함께 정의. ID로 식별:

| ID | 이름 | Props | 사용처 |
|----|------|-------|--------|
| `C-001` | NoticeCard | title, author, pinned, createdAt | 홈, 게시판 |
| `C-002` | EventListItem | title, date, rsvpStatus | 홈, 일정 |
| `C-003` | CommentThread | postId, comments[] | 게시글 상세 |
| `C-004` | RoleBadge | role | 모든 사용자 표시 |
| ... | ... | ... | ... |

### 5. 디자인 토큰
Frontend의 Tailwind config로 바로 이식 가능한 형태:

```yaml
color:
  primary: "#1E40AF"    # 신뢰감 있는 블루 (학교 톤 조정 가능)
  surface: "#FFFFFF"
  bg: "#F8FAFC"
  text: "#0F172A"
  muted: "#64748B"
  danger: "#DC2626"
typography:
  family: "Pretendard, system-ui"
  scale: { xs:12, sm:14, base:16, lg:18, xl:20, '2xl':24 }
spacing: { 1:4, 2:8, 3:12, 4:16, 6:24, 8:32 }
radius: { sm:6, md:10, lg:16, full:9999 }
```

### 6. 상태 처리 규칙
- **빈 상태**: 아이콘 + 한 줄 설명 + 1차 CTA
- **로딩**: 스켈레톤 우선, 1초 미만 작업엔 인디케이터 없이
- **에러**: 메시지 + 재시도 버튼, 네트워크 vs 권한 vs 서버 구분

### 7. 접근성 체크
- 터치 타겟 최소 44×44px
- 본문 텍스트 색 대비 4.5:1 이상
- 폼 입력 시 키보드 IME 안전 (한글 조합 중 자동 제출 금지)
- 동적 변경 영역은 ARIA live region
