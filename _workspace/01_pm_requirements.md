## 1. 제품 비전

> **한 문장:** "대학원 원우회 구성원이 공지·소통·일정·회비를 한 곳에서 모바일로 빠르게 처리할 수 있는, 학과 단위의 비공개 커뮤니티 PWA."

핵심 가치 제안:
- **단일 진입점**: 카톡 공지방, 구글 캘린더, 송금 알림으로 흩어진 정보를 통합
- **모바일 우선**: 노트북 없이 손에서 모든 핵심 액션 가능
- **저운영 비용**: 임원 임기 1년 단위 인수인계가 쉬운 단순 권한 모델

## 2. 타겟 사용자 (페르소나)

### 페르소나 A. 신입 원우 "지민" (석사 1학기)
- **상황**: 3월 입학, 학과 구조도 사람도 모름. 첫 행사 일정을 놓치고 싶지 않음.
- **사용 패턴**:
  - 1~2주차: 공지 정독, 임원 명단 확인, 행사 RSVP
  - 1학기: 주 2~3회 게시판 열람, 가끔 질문글 작성
  - 졸업까지: 알림만 받고 행사 일정만 확인하는 라이트 유저로 전환
- **핵심 니즈**: 진입장벽 없는 가입, 누가 누구인지 명확한 회원 디렉토리, 행사 한눈에 보기

### 페르소나 B. 임원/총무 "현우" (박사 3년차, 총무)
- **상황**: 1년 임기. 공지 작성, 회비 수납 확인, 행사 운영을 혼자 또는 2~3명이 함.
- **사용 패턴**:
  - 매주: 공지 1~2건, 회비 미납자 확인, 댓글 모니터링
  - 학기 초/말: 행사 등록, 참가자 명단 추출
  - 임기 말: 후임에게 권한 양도
- **핵심 니즈**: 빠른 공지 작성(템플릿/핀 고정), 회비 납부 현황 일괄 확인, 회원 권한 위임이 쉬운 UI

### 페르소나 C. 고학년/졸업 예정자 "수아" (박사 수료, 졸업 준비)
- **상황**: 연구실에서 거의 살며 원우회 활동에는 소극적. 단톡방은 음소거.
- **사용 패턴**:
  - 월 1~2회: 알림 받은 공지만 확인
  - 학기 1회: 정기 모임 RSVP
  - 졸업 후: 계정 비활성화 또는 졸업생 모드로 전환(P2)
- **핵심 니즈**: 알림 노이즈 최소화, 중요 공지만 푸시, 부재 시에도 회비 납부 가능

## 3. 사용자 스토리 (P0/P1/P2)

> P0 = MVP 필수. P1 = MVP 직후 차순. P2 = 향후 검토. MVP 범위를 좁게 잡기 위해 P0는 핵심 8개로 한정.

### 3.1 인증/계정
- **[P0] US-01**: As a 신입 원우, I want 이메일+학번으로 가입 신청을 하고 임원 승인 후 활성화되기를, so that 외부인 유입 없이 학과 구성원만 모인다.
- **[P0] US-02**: As a 회원, I want 이메일/비밀번호로 로그인하기를, so that 매번 인증 없이 빠르게 진입한다.
- **[P0] US-03**: As a 회원, I want 이름/입학년도/연구실/연락처를 프로필에 등록·수정하기를, so that 동료들이 나를 식별할 수 있다.
- **[P1] US-04**: As a 회원, I want 비밀번호 재설정 메일을 받기를, so that 잊었을 때 복구한다.
- **[P2] US-05**: As a 회원, I want 학교 SSO로 로그인하기를, so that 별도 비밀번호가 필요 없다.

### 3.2 공지
- **[P0] US-10**: As a 임원, I want 공지글을 작성·수정·삭제하기를, so that 학사/행사 정보를 전달한다.
- **[P0] US-11**: As a 회원, I want 공지 목록을 최신순으로 보고 상세 페이지에서 읽기를, so that 놓친 정보를 따라잡는다.
- **[P1] US-12**: As a 임원, I want 중요 공지를 상단에 핀 고정하기를, so that 신입이 먼저 본다.
- **[P1] US-13**: As a 회원, I want 새 공지가 올라오면 푸시(웹 푸시) 알림을 받기를, so that 즉시 안다.
- **[P2] US-14**: As a 회원, I want 공지에 첨부파일(PDF/이미지)을 다운로드하기를.

### 3.3 게시판/소통
- **[P0] US-20**: As a 회원, I want 자유 게시판에 글을 작성·조회·삭제하기를, so that 동료와 소통한다.
- **[P0] US-21**: As a 회원, I want 게시글에 댓글을 달기를, so that 가벼운 대화가 가능하다.
- **[P1] US-22**: As a 회원, I want 게시글/댓글에 좋아요를 누르기를.
- **[P1] US-23**: As a 회원, I want 게시판을 카테고리(질문/공유/모집)로 구분하기를.
- **[P2] US-24**: As a 회원, I want 제목/본문을 키워드로 검색하기를.
- **[P2] US-25**: As a 회원, I want 부적절한 글을 신고하기를.

### 3.4 일정
- **[P0] US-30**: As a 임원, I want 행사 일정(제목/일시/장소/설명)을 등록하기를, so that 회원이 일정을 안다.
- **[P0] US-31**: As a 회원, I want 다가오는 일정 목록과 월 캘린더 뷰를 보기를, so that 한눈에 파악한다.
- **[P1] US-32**: As a 회원, I want 일정에 참석/불참 RSVP를 표시하기를.
- **[P1] US-33**: As a 임원, I want RSVP 명단을 다운로드(CSV)하기를.
- **[P2] US-34**: As a 회원, I want 일정을 개인 캘린더(.ics)로 내보내기를.

### 3.5 회비/행사 관리
- **[P0] US-40**: As a 임원, I want 학기 단위 회비 항목(예: "2026-1학기 회비")을 생성·수정·삭제하기를, so that 학기마다 납부 대상을 정의한다.
- **[P0] US-41**: As a 회원, I want 내 학기별 회비 납부 상태(납부/미납/면제)와 마지막 갱신일을 조회하기를, so that 내 납부 여부를 확인하고 누락 시 임원에게 문의한다.
- **[P0] US-42**: As a 임원, I want 회원별 회비 납부 여부를 체크박스로 토글하고 메모(예: 입금일, 부분 납부 사유)를 남기기를, so that 계좌이체 확인 후 수기로 기록한다.
- **[P0] US-43**: As a 임원, I want 특정 학기 회비 항목에 대한 미납자 목록을 한 화면에서 조회하기를, so that 독촉 대상 파악과 후속 연락이 쉽다.
- **[P2] US-44**: As a 회원, I want 행사 참가비를 앱 내에서 결제하기를. (PG 연동 필요 — 별도 검토)
- **[P2] US-45**: As a 임원, I want 회비 자동 미납 알림(인앱/푸시)을 보내기를.

### 3.6 회원 관리/디렉토리
- **[P0] US-50**: As a 임원, I want 가입 신청자를 승인/반려하기를, so that 회원 자격을 통제한다.
- **[P1] US-51**: As a 회원, I want 회원 디렉토리(이름/기수/연구실)를 검색하기를.
- **[P1] US-52**: As a 관리자, I want 회원에게 임원 권한을 위임/회수하기를, so that 임기 인수인계가 가능하다.
- **[P2] US-53**: As a 회원, I want 졸업생 모드로 전환하여 알림만 최소 수신하기를.

### 3.7 관리/모더레이션
- **[P1] US-60**: As a 임원, I want 신고된 게시글을 숨김 처리하기를.
- **[P2] US-61**: As a 관리자, I want 회원을 정지/탈퇴 처리하기를.

> **MVP(P0) 합계: 15개 스토리** (인증 3, 공지 2, 게시판 2, 일정 2, 회비 4, 회원관리 1, 프로필 1)
> 푸시·핀·검색·신고는 P1 이후로 미루고, 회비는 PG 없이 수기 체크 수준으로 P0에 포함하여 첫 릴리스를 5~7주 안에 끝낼 수 있게 함.

## 5. 기능 명세 (화면/도메인별)

### 5.1 인증/온보딩
- **가입 신청 화면**: 이메일, 비밀번호, 이름, 학번, 입학년도, 연구실(선택), 연락처 입력 → "승인 대기" 상태로 저장
- **로그인 화면**: 이메일/비밀번호
- **승인 대기 안내 화면**: 임원이 승인할 때까지 차단
- **프로필 화면**: 본인 정보 표시·수정, 비밀번호 변경

### 5.2 홈
- 상단: 핀 공지(P1) → 최신 공지 3건 → 다가오는 일정 3건
- 하단 탭(모바일): 홈 / 공지 / 게시판 / 일정 / 더보기

### 5.3 공지
- 공지 목록 (최신순, 핀은 상단 — P1)
- 공지 상세 (작성자/날짜/본문/첨부 — 첨부는 P2)
- 공지 작성 (임원 이상, 리치 텍스트 에디터 또는 마크다운)

### 5.4 게시판
- 카테고리 탭(P1) — MVP에선 단일 게시판
- 게시글 목록, 게시글 상세 + 댓글 스레드
- 작성/수정 화면

### 5.5 일정
- 리스트 뷰 (P0) + 캘린더 뷰 (P0, 월 단위)
- 일정 상세: 제목/일시/장소/설명/RSVP 버튼(P1)
- 일정 등록 (임원 이상)

### 5.6 회비 (P0, 수기 운영)
- **회비 항목 관리 (임원)**: 학기 단위 회비 항목 생성·수정·삭제. 필드 — 학기 라벨(예: "2026-1학기"), 금액(원), 납부 마감일(선택), 설명/계좌 안내(자유 텍스트).
- **납부 현황 매트릭스 (임원)**: 행=회원, 열=학기 회비 항목. 셀에 상태(납부/미납/면제) 토글 + 메모(입금일/부분납 사유). 학기 컬럼 헤더에 미납자 수 카운트.
- **미납자 목록 (임원)**: 특정 회비 항목 선택 → 미납 회원 목록(이름/기수/연락처/메모). CSV 다운로드는 P1.
- **내 납부 내역 (회원)**: 학기별 상태/금액/마지막 갱신일/임원 메모(공개 메모만). 본인 분만 조회.
- **결제 수단**: 앱 외부 계좌이체. 앱 내 PG 결제 없음. 계좌 안내는 회비 항목 설명 필드에 자유 텍스트로 노출.
- **알림**: 자동 미납 알림 없음(P2). 임원이 필요 시 공지 또는 외부 메신저로 직접 안내.

### 5.7 회원 관리 (P0 일부)
- **가입 승인 큐 (P0)**: 임원 화면, 대기 명단 → 승인/반려
- **회원 디렉토리 (P1)**: 검색·필터(기수/연구실)
- **권한 관리 (P1)**: 관리자만 접근, 회원의 역할 변경

### 5.8 더보기/설정
- 알림 설정(P1), 약관/개인정보, 로그아웃, 탈퇴

## 6. 비기능 요건

| 카테고리 | 요건 |
|---------|------|
| **플랫폼** | PWA (Next.js 14 App Router). iOS/Android 홈 화면 추가 지원. 앱스토어 등록은 하지 않음 (ASSUMPTION). |
| **반응형** | 모바일 우선(360~430px). 태블릿/데스크톱은 자동 확장(컨테이너 폭 제한). |
| **언어/지역** | 한국어 단일. 시간대 KST 고정. 날짜 표기 YYYY.MM.DD (요일). |
| **접근성** | WCAG 2.1 AA 목표. 키보드 포커스, 4.5:1 명도비, alt 텍스트 필수. |
| **성능** | 첫 페이지 LCP < 2.5s (3G Fast 기준). 페이지 전환 < 300ms 체감. |
| **오프라인** | PWA 캐시로 마지막 본 공지/일정 오프라인 열람 가능 (P1). |
| **개인정보** | 학번·연락처는 본인+임원만 열람. 디렉토리에는 이름/기수/연구실만 노출. |
| **데이터 보존** | 탈퇴 시 30일 유예 후 개인정보 익명화. 게시글은 "(탈퇴회원)"으로 표기 유지. |
| **보안** | 비밀번호 해시(bcrypt 또는 Supabase Auth 기본), HTTPS 강제, CSRF 방어. |
| **인증/인가** | Supabase Auth + Row Level Security(RLS)로 권한 매트릭스 강제. |
| **저장소** | Supabase Postgres + Storage (첨부 파일). |
| **알림** | P0는 인앱 알림만. 웹 푸시는 P1. 이메일 알림은 P2. |
| **백업** | Supabase 자동 백업(일 1회) 의존. 별도 운영 백업은 P2. |
| **감사 로그** | 권한 변경/공지 삭제/회원 승인 이력은 DB에 기록 (P1). |
| **다국어** | 미지원. 향후 영어 추가 가능성 열어둠. |

## 7. 열린 질문 (사용자 확인 필요)

> 명시되지 않은 항목은 합리적 기본값으로 가정(ASSUMPTION)했습니다. 아래 항목을 사용자가 정정하면 v0.2로 갱신합니다.

### 7.1 핵심 가정 (반드시 사후 확인)
1. **[ASSUMPTION] 회원 범위**: "단일 학과 단일 원우회" 가정. 여러 학과/기수를 분리하는 멀티 그룹 구조는 미지원. → 만약 여러 학과가 한 앱을 쓰면 도메인 모델이 크게 바뀜.
2. **[ASSUMPTION] 가입 방식**: 이메일+학번+임원 승인제. 학교 SSO(고려대/서울대 포털 등) 연동은 P2. → SSO가 필수면 인증 스택 재설계 필요.
3. **[CONFIRMED 2026-05-20] 회비 시스템 수준**: P0에 수기 회비 관리 포함. 계좌이체 후 임원이 납부 상태를 체크하는 방식이며 앱 내 PG/온라인 결제는 없음. 학기 단위 회비 항목, 회원별 상태(납부/미납/면제) + 메모, 미납자 목록을 제공. → 앱 내 실결제가 향후 필요해지면 PG사 선정/계약/PCI 이슈가 추가됨(P2 US-44 참조).
4. **[ASSUMPTION] 권한 모델**: 일반회원/임원/관리자 3단. 학번 대표/연구실장 같은 중간 역할은 없음.
5. **[ASSUMPTION] 비공개 정책**: 비로그인 시 어떤 페이지도 열람 불가(랜딩 + 로그인만 노출). → 외부 홍보용 공개 페이지가 필요한가?
6. **[ASSUMPTION] 졸업생 처리**: MVP에서는 일반회원과 동일. 졸업생 모드/동문 네트워크는 P2.
7. **[ASSUMPTION] 푸시 알림**: P0는 인앱만, P1에서 웹 푸시 도입. iOS 웹 푸시 제한은 사용자에게 안내 필요.
8. **[ASSUMPTION] 첨부파일**: 공지 첨부는 P2로 미룸. MVP에서는 본문 텍스트+링크만.

### 7.2 운영/정책 질문
9. 원우회 규모는 몇 명인가? (10명 vs 200명에 따라 디렉토리·푸시 설계 변동)
